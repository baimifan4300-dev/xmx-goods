# 04 · 付款/退款流水与完整备份设计

## 1. 付款模型的目标

必须同时满足：

- 定金、尾款、分批付款、运费、优惠不重复统计；
- 已预订 ≠ 已拥有；
- 已付定金 ≠ 商品总价已付；
- 已入手由「收货/拥有状态」决定，不由付款决定；
- 取消/退款不能把历史支出算错；
- 每件商品/每卷书都能追溯实际支出；
- 月度/年度报告按**实际付款日期**统计。

## 2. 表关系

```text
orders 1 ── N order_items
orders 1 ── N payment_records
order_items N ── 1 products / books（多态）
orders 1 ── N refund records（仍是 payment_records，kind='refund'）
```

- `orders` 是订单头：商品总额、运费、优惠、计划定金、尾款截止日。
- `order_items` 是订单里的商品/书籍行；支持一单多件。
- `payment_records` 是实际资金流水：定金、尾款、全款、运费、退款、调整。
- 不把「已付总额」存进 `orders`，避免两台设备同时付款时覆盖。

## 3. 金额字段定义

| 字段 | 含义 | 是否参与计算 |
|---|---|---|
| `orders.total_amount` | 商品总额（不含运费、不含优惠） | 是 |
| `orders.shipping_fee` | 运费 | 是，加到应付 |
| `orders.discount_amount` | 优惠金额（正数=减钱） | 是，从应付减 |
| `orders.deposit_planned` | 计划定金（展示用） | **否**，不能与实付定金相加 |
| `payment_records.amount` | 实际收/付金额 | 是 |
| `payment_records.kind` | deposit/balance/full/shipping/refund/adjustment | 决定符号 |
| `order_items.unit_price` | 单件商品价 | 用于分摊 |
| `order_items.line_discount` | 行优惠 | 用于分摊 |
| `order_items.allocated_amount` | 可选：该行实际分摊金额 | 若为空，按行占比计算 |

## 4. 计算公式

### 4.1 订单应付

```text
payable = total_amount + shipping_fee - discount_amount
```

`discount_amount` 必须 >= 0；如果遇到加价，用负的 `line_discount`/`adjustment`，不要用负优惠。

### 4.2 订单已付（净额）

```text
gross_paid = sum(amount where kind in ('deposit','balance','full','shipping','adjustment'))
refunded   = sum(amount where kind = 'refund')
paid       = gross_paid - refunded
```

- `refund` 存正数，汇总时减。
- `adjustment` 允许正负；用于抹零/补差。
- 定金和尾款都只是 `payment_records` 的一种，不会在 `orders` 里再扣一次。

### 4.3 待补尾款

```text
balance_due = greatest(payable - paid, 0)
```

- 如果 `paid > payable`，余额为 0，超额部分在报表中显示为「多付/待退」，不自动变成负尾款。
- 未收到货不影响 `balance_due`；但未收到货不计入「已拥有」。

### 4.4 单件实际支出

如果订单只有一件：

```text
item_paid = paid
```

如果一单多件：

```text
line_total_i = unit_price_i * quantity_i - line_discount_i
allocated_i  = paid * line_total_i / sum(line_total)
```

- 若手工填了 `order_items.allocated_amount`，优先用它。
- 运费/优惠按行总额比例分摊；退款也按同一比例分摊到行。
- 报告按 `order_items` 的 `allocated_amount` 汇总，避免订单总额重复算到每件商品。

### 4.5 实际购买价与市场价

- `collections.purchase_price` / `books.purchase_price` 是**兼容字段/展示值**，用于没有订单明细的旧数据。
- 有订单时，实际支出以 `payment_records` 为准；`purchase_price` 不参与报告合计，避免重复。
- `price_history` 可以记录 `price_type='purchase'` 的历史快照，但**报告支出只读 `payment_records`**，不把 price_history 再加一遍。
- 市场价格 `market_price` 只是参考价，永远不计入实际支出。

## 5. 状态与拥有规则

`status_definitions.counts_as_owned`：

- `owned`（已入手）= true
- `want/watch/preorder/balance/cancelled` = false

统计规则：

- 收藏数量/集齐成就/拥有率：只统计 `counts_as_owned=true` 且 `deleted_at is null` 的记录。
- 已预订/待补尾款：计入「待付款/待收货」，不计入已拥有。
- 已取消：不计入已拥有，也不计入待补尾款；已付款项若有退款，用 refund 流水冲减。
- 已入手应由用户把状态改为 `owned`（并填写 `received_at`）触发，不能仅凭付款自动变 owned。
- 旧 V5 收藏行迁移为 `owned`，`received_at` 可空；不伪造日期。

## 6. 典型场景

### 场景 A：定金 50，尾款 150，运费 10，优惠 0

- `total_amount=200`, `shipping_fee=10`, `discount=0`, `payable=210`
- 付款：deposit 50、balance 150、shipping 10 → `paid=210`
- `balance_due=0`；已拥有需状态=owned。

### 场景 B：只付定金 50，商品 200，运费 10

- `payable=210`, `paid=50`
- `balance_due=160`
- 状态=preorder/balance，不计入已拥有。

### 场景 C：取消订单，退定金 50

- 付款：deposit 50；退款：refund 50
- `paid=0`；`balance_due=0`（订单状态 cancelled）
- 报告：支出 50、退款 50，净支出 0；不能只记 50 支出而不记退款。

### 场景 D：一单两件，A 100、B 50，运费 15，实付 165

- `line_total A=100`, `B=50`；`paid=165`
- `allocated A=110`, `B=55`（按 2:1 分摊运费）
- 报告按 A/B 分摊，不把 165 同时算给两件。

### 场景 E：多付 5 元

- `payable=210`, `paid=215`
- `balance_due=0`；报表「多付 5」，不出现负尾款。

## 7. 待补尾款页面数据

`v_pending_balances` 输出：

- `order_id, order_no, shop_name, payable, paid, balance_due`
- `balance_due_date`、`days_left`、`overdue`（`balance_due_date < current_date`）
- 关联商品/书籍行（订单行）
- 状态为 `open` 且 `balance_due > 0`

汇总卡：

- 待补总金额 = `sum(balance_due)`
- 待付款订单数 = `count(*)`
- 即将截止 = 7 天内
- 已逾期 = `overdue=true`

## 8. 月度/年度报告规则

- 支出按 `payment_records.paid_at` 所属月份/年份统计，不按商品创建时间。
- 定金、尾款、运费、退款分别列示；总支出 = 付款合计 - 退款合计。
- 已拥有数量按 `counts_as_owned` 且 `received_at`/状态变更时间统计（没有历史状态事件时，用 `updated_at` 或 `purchase_date` 的明确规则，不能伪造）。
- 未收到货的预订不计入已拥有。
- 取消订单不删除历史流水；报告显示「已取消/已退款」。
- 书籍按「册数」和「套数」分别统计；套书完成率按 `book_set_progress`。

> 需要一个 `status_history` 表才能精确统计「某月新增已拥有」；P0 设计建议增加 `status_history`（见第 9 节），否则只能用当前状态 + 日期近似。

## 9. 建议补充：`status_history`

为了准确做月报/年报和「获得时间」：

| 列 | 类型 | 说明 |
|---|---|---|
| `owner_id` | uuid | |
| `id` | uuid | PK |
| `entity_type` | text | product/book |
| `entity_id` | text | |
| `from_status_id` | text null | |
| `to_status_id` | text | |
| `changed_at` | timestamptz | |
| `note` | text | |

索引 `(owner_id,entity_type,entity_id,changed_at)`、`(owner_id,to_status_id,changed_at)`。
只追加，不更新；状态变更时触发器写入。这样报告可以精确按时间统计，不依赖 `updated_at`。

## 10. 完整备份 v4

### 10.1 格式

```json
{
  "format": "xmx-collection-backup",
  "formatVersion": 4,
  "schemaVersion": "2026-11-supabase-v2",
  "appVersion": "6.0.0",
  "exportedAt": "2026-11-24T...",
  "owner": { "id": "...", "email": "..." },
  "counts": { "...": 0 },
  "data": { "...": [] }
}
```

兼容：

- 读取 `formatVersion <= 4`；
- `formatVersion === 2`（V5）走兼容映射；
- 更高版本拒绝并提示升级。

### 10.4 恢复顺序

1. 读取/校验 manifest、格式、版本、图片 SHA-256；
2. 预览统计：新增/覆盖/冲突/缺失图片；
3. 自动生成当前数据快照（本地 ZIP 或云端临时备份）；
4. 恢复定义类：类型、状态、分类、字段、地点、系列、书籍类型、成就；
5. 恢复主数据：作品/角色、商品、书籍套/卷；
6. 恢复关系/流水：collections、series_items、orders/order_items/payment_records、price_history、sales、user_achievements；
7. 恢复图片：按 manifest 上传 Storage，写 `item_images`；
8. 恢复 settings；
9. 输出报告：成功/跳过/失败/警告/缺失图片。

### 10.5 恢复模式

- **合并**：只补缺失，不覆盖；适合新设备。
- **覆盖同 ID**：覆盖同 ID 记录；恢复前自动备份当前数据。
- **只恢复配置**：只恢复状态/分类/字段/徽章/地点，不动商品/收藏。
- **包含回收站**：默认包含软删除记录；恢复后仍在回收站。

不允许静默清空当前数据；恢复不会删除备份中不存在的现有记录（除非用户显式选择「替换全部」，本版不做）。

### 10.6 V5 v2 备份兼容映射

| v2 数据 | v4 映射 |
|---|---|
| `products` | `products`（`market_price_date=null`） |
| `collections` | `collections`（`status_id='owned'`，补 `deleted_at=null`） |
| `wishlist` | `collections`（`status_id='want'`） |
| `boardCategories` | `boardCategories` |
| `boardAssignments` | `boardAssignments` |
| `productImages` | `productImages` + 镜像 `itemImages` |
| `settings` | `settings` |
| 无 | `books/bookSets/orders/...` 为空 |
| `mainCategories/works/characters` | 参考数据，恢复时只补缺失，不覆盖 20 内置 |

## 11. 回收站与备份的关系

- 软删除记录默认进入备份；恢复后仍在回收站。
- 永久删除前自动备份；备份中保留被删记录，便于事后恢复。
- 回收站按类型显示：商品、书籍、套书、系列、订单、图片、分类/状态/字段配置。
- 恢复顺序：父记录 → 子记录；父记录未恢复时，子记录显示「父记录在回收站」。

## 12. 备份体积与性能

- 1537 条商品 + 57 张合集图 + 1296 缩略图约 55MB；V6 多图相册/徽章会增加。
- 建议：
  - 保留「包含原始合集图」开关；
  - 图片按原文件 STORE，不重复压缩；
  - manifest 写 SHA-256，恢复时校验；
  - 手机端备份显示进度、可取消；
  - 大备份分卷（>500MB）作为后续优化，本版先单 ZIP。

## 13. 关键结论

- 付款必须用流水，不能只存「已付总额」。
- 定金/尾款/运费/退款/优惠必须有明确符号规则。
- 报告按付款日期，不按商品创建日期。
- 已拥有只由状态决定，不由付款决定。
- 备份 v4 必须包含所有配置、流水、软删除和图片；v2 必须可恢复。
