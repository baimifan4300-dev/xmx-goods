# 云端部署与迁移

本文按“从零创建 Supabase → 部署 Vercel → 首次登录迁移 V4 数据”的顺序说明。所有 SQL 都在 `supabase/migrations/`。

> 不要把 `service_role` key 写进 `config.js`、Vercel 前端环境变量或任何浏览器代码。前端只用 anon public key。

---

## 一、创建 Supabase 项目

1. 打开 https://supabase.com/dashboard ，新建项目。
2. 记下 **Project URL**（形如 `https://abcdefgh.supabase.co`）和 **anon public key**（Project Settings → API）。
3. 项目创建完成后，进入 **SQL Editor**。

---

## 二、初始化数据库

### 方式 A：SQL Editor（推荐给非开发者）

按顺序新建查询并执行：

1. `supabase/migrations/202611230001_schema.sql`
2. `supabase/migrations/202611230002_rls.sql`
3. `supabase/migrations/202611230003_seed.sql`
4. `supabase/migrations/202611230004_grants.sql`

四份文件都是幂等的（重复执行不会重复插入 20 个主分类；策略会先 drop 再 create；GRANT 可重复执行）。如果中途报错，先解决错误，不要跳过。

> **`004_grants.sql` 不能省。** Supabase 新建项目不会自动把 `public` 表的读写权限授予 `anon` / `authenticated`。只执行前 3 份时，注册/登录会成功，但一读商品就报 `permission denied for table products`，前端显示“没有权限执行该操作，请确认已登录且数据属于当前账号”。

### 方式 B：Supabase CLI

```bash
npm install -g supabase
supabase login
supabase link --project-ref <your-project-ref>
supabase db push
```

`supabase/migrations/` 下的时间戳文件会按顺序执行。

### 执行后检查

在 SQL Editor 执行：

```sql
select count(*) from public.main_categories; -- 应为 20
select key, label, sort_order from public.main_categories order by sort_order;
select id, name from public.works;            -- gyly / 光与夜之恋
select id, name from public.characters;        -- xmx / 夏鸣星
select has_table_privilege('authenticated','public.products','select') as products_select,
       has_table_privilege('authenticated','public.user_settings','select') as settings_select,
       has_table_privilege('anon','public.main_categories','select') as anon_categories;
-- 三项都应为 true
```

`storage.buckets` 中应出现 `product-images`，`public = false`，文件上限 12MB。

## 三、Auth 设置

进入 **Authentication**：

1. **Providers → Email** 开启。
2. **URL Configuration**：
   - Site URL：`https://xmx-goods.vercel.app`
   - Redirect URLs 增加：
     - `https://xmx-goods.vercel.app/**`
     - `http://127.0.0.1:8765/**`（本地调试）
3. 如果不想每次注册都收确认邮件：
   - **Authentication → Providers → Email → Confirm email** 关闭；或
   - 配置自定义 SMTP，保留确认邮件。
4. 密码最短 6 位（前端也限制 6 位）。

注册后，`auth.users` 插入会自动创建 `profiles` 与 `user_settings`（触发器）。

## 四、配置前端

### 本地开发

复制模板并填写：

```bash
cp config.example.js config.js
```

或直接编辑 `config.js`：

```js
window.XMX_CONFIG = {
  supabaseUrl: "https://<project-ref>.supabase.co",
  supabaseAnonKey: "<anon public key>",
  storageBucket: "product-images",
  appVersion: "5.0.0",
  demoFallback: false
};
```

也可以使用环境变量：

```bash
cp .env.example .env
# 填 SUPABASE_URL / SUPABASE_ANON_KEY
npm run build
```

`scripts/build.mjs` 检测到环境变量时会生成 `config.js`；没有环境变量时保留已有 `config.js`。

启动：

```bash
npm run dev
# 打开 http://127.0.0.1:8765/
```

### Vercel

1. 把项目推到 GitHub 仓库（建议独立分支，见文末）。
2. Vercel → New Project → 导入仓库。
3. Build Command：`npm run build`
4. Output Directory：`.`
5. Environment Variables 添加：
   - `SUPABASE_URL` = `https://<project-ref>.supabase.co`
   - `SUPABASE_ANON_KEY` = anon public key
6. Deploy。

`vercel.json` 已配置构建、CSP（允许 `*.supabase.co` / `wss://*.supabase.co`）和缓存头。若使用自定义域名，把域名加入 Supabase Auth 的 Site URL/Redirect URLs。

> 部署后先打开 `https://你的域名/`，应该看到登录/注册页，而不是本地预览。若看到“还差一步：连接 Supabase”，说明 `config.js` 没有生成，检查 Vercel 环境变量和构建日志。

## 五、首次登录：迁移 1537 条 + V4 本机数据

### 账号初始化

注册并登录后，如果云端 `products` 为空，网站会自动：

1. 读取 `data/gyly/xmx/products.json` 的 1537 条商品；
2. 读取当前浏览器中的 V4：
   - `xmx.collection.v1`（收藏、愿望）
   - `xmx.boards.v1.gyly.xmx`（联动/满赠分类与归属）
   - `xmx-goods-products-v1`（如果存在 V1 用户商品）
3. 分批写入 Supabase（每批 200 条，使用 upsert + 忽略重复，可重复执行）；
4. 生成默认满赠分类（吧唧/纸片/亚克力/其他）并归类 77 件满赠商品；
5. 写入 `user_settings.migration` 与 `defaultsInitialized`；
6. 自动下载 `xmx-v4-premigration-*.json` 快照；**不删除本机旧键**。

### 迁移结果核对

- 全图鉴总数应为 1537（若之前有站内新增，则更多）。
- 20 个主分类顺序不变。
- 收藏/愿望数量与 V4 本机一致。
- 联动 347 件、满赠 77 件；满赠默认分类计数约为 吧唧 7 / 纸片 41 / 亚克力 6 / 其他 23（以实际数据为准）。
- “分类与商品归属已同步到云端”提示出现。

### 在另一台设备合并本机数据

如果先在手机注册（云端空，自动导入 1537 条），再在电脑登录，电脑浏览器里的 V4 收藏不会自动覆盖云端。登录后会出现“检测到本机 V4 数据”的提示，点“合并到云端”即可；合并只补充缺失记录，不覆盖云端已有购买价。也可以从“账户 → 从本机旧数据合并”手动执行。

### 迁移安全检查

- 所有写入都按 `(owner_id, id)` / `(owner_id, product_id)` 唯一键 upsert，不会重复商品/收藏。
- 分类同名冲突会跳过并保留云端分类；归属会按名称映射，避免外键失败。
- 迁移中途失败可重新登录重试；已经写入的数据不会重复。
- V4 的 JSON 文件 `data/gyly/xmx/products.json` 不会被修改。

## 六、部署后验收

1. 注册账号，确认 1537 条商品出现。
2. 新增一件商品，上传一张图；确认列表、详情、图片都正常。
3. 在手机/另一台电脑登录同一账号，刷新，确认商品与图片存在。
4. 修改收藏数量、购买价、市场价，确认三项互不覆盖。
5. 两个设备同时编辑同一商品，确认弹出冲突选择。
6. 账户 → 完整备份，下载 ZIP；用 `unzip -l` 确认包含 `manifest.json`、`data.json`、`images/uploads/`。
7. 删除一件站内商品；账户 → 从备份恢复；确认商品、收藏、图片回来。
8. 账户 → 退出登录，再登录，确认数据仍在。

详细验收项见 [验收清单.md](验收清单.md)。

## 七、常见问题

### 登录后看不到商品 / 一直 0 件

- 检查 `202611230001_schema.sql`、`002_rls.sql`、`003_seed.sql`、`004_grants.sql` 是否全部执行。
- 如果控制台是 `permission denied for table products` / `user_settings`，就是漏了 `004_grants.sql`；补执行即可，不需要重建数据库。
- 检查浏览器控制台是否有 `relation "public.works" does not exist` 或 RLS 错误。
- 检查 `auth.users` 触发器是否创建：`select * from public.profiles;`。
- 检查 `products` 是否有当前用户数据：`select count(*) from public.products where owner_id = auth.uid();`（在登录后的 SQL Editor 里手动指定用户）。

### 图片上传 403 / 404

- 确认 Storage 桶 `product-images` 存在且为 private。
- 确认 `002_rls.sql` 里的 Storage 策略已执行。
- 确认 `config.js` 的 `storageBucket` 是 `product-images`。
- 确认上传路径第一段是当前用户 UUID（代码已处理）。

### 图片显示不出来

- 私有桶使用 1 小时签名 URL；刷新页面或重新聚焦会自动续签。
- 检查 CSP 是否允许 `https://*.supabase.co` 和 `wss://*.supabase.co`（`vercel.json` 已配置）。
- 检查 Storage 策略 `product_images_storage_select_own`。

### 注册后收不到确认邮件

- 开发阶段可在 Supabase Auth 关闭 Confirm email；或配置 SMTP。
- 如果已经开启确认，登录页会提示“邮箱尚未确认”；可点“重发确认邮件”。

### Vercel 构建失败

- 确认 Node 版本 ≥ 20。
- 确认环境变量 `SUPABASE_URL` / `SUPABASE_ANON_KEY` 没有多余空格。
- 本地执行 `npm ci && npm run build` 复现。
- `app.js` 是构建产物；不要只上传 `src/` 而忘记构建。

### 想回到 V4 界面

V4 原目录/压缩包未改动；本仓库的 `data/` 与 `assets/` 与 V4 一致。回滚时用 V4 的 `index.html/style.css/app.js` 覆盖三个文件即可，云端数据仍在 Supabase，不会丢失。

## 八、Git 分支建议

本升级应放在独立分支，不直接覆盖 `main`：

```bash
git checkout -b feature/supabase-cloud
git add .
git commit -m "feat: supabase cloud sync, product management, backup/restore"
git push -u origin feature/supabase-cloud
```

在 GitHub 开 PR，Vercel Preview 部署验证后再合并 `main`。不要把 `.env`、`config.js` 中的真实密钥提交到 public 仓库；推荐用 Vercel 环境变量。
