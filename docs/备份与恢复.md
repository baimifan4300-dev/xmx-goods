# 备份与恢复

网站内的“账户 → 完整备份”不依赖 Supabase 平台备份，导出的是可离线保存、可完整恢复的 ZIP 包。

---

## 1. 备份包含什么

| 内容 | 是否包含 |
|---|---|
| 全部商品（原始 1537 + 站内新增） | ✅ `data.json` + `payload` 全字段 |
| 20 个主分类及顺序 | ✅ `data.data.mainCategories` |
| 联动/满赠自定义分类 | ✅ `boardCategories` |
| 商品与子分类归属 | ✅ `boardAssignments` |
| 收藏（数量/购买价/日期/备注） | ✅ `collections` |
| 愿望清单 | ✅ `wishlist` |
| 市场价格 | ✅ 商品 `marketPrice` + `market_price` |
| 用户上传高清图/封面/缩略图 | ✅ `images/uploads/` |
| 原始合集图与裁切缩略图 | ✅ `images/base/`（可选，默认包含） |
| 图片元数据 | ✅ `productImages` + `manifest.json` |
| 用户设置 | ✅ `settings` |
| 版本号/导出时间/结构版本 | ✅ `manifest.json` + `data.json` |

不包含：登录密码、Supabase 密钥、service_role、其他用户数据。

---

## 2. 导出步骤

1. 登录网站。
2. 右上角头像/“账户” → **完整备份（含图片）**。
3. 选择：
   - **包含原始合集图与缩略图**（默认勾选，完整归档约 41–55MB）；
   - **包含列表缩略图**（默认勾选）。
4. 点“开始导出”，等待进度完成；浏览器下载 `xmx-goods-backup-YYYYMMDD-HHmmss.zip`。
5. 建议把 ZIP 存到网盘/移动硬盘，并保留至少两份。

> 手机端内存较小，可取消“包含原始合集图”，只备份数据 + 用户上传图；原始图仍在项目 `assets/` 中。

## 4. 恢复步骤

1. 账户 → **从备份恢复**，选择 ZIP。
2. 网站会：
   - 校验 `format/formatVersion`；
   - 校验图片文件是否存在；
   - 对每个图片计算 SHA-256 与 manifest 对比；
   - 显示商品/收藏/分类/图片数量。
3. 选择恢复模式：
   - **合并（推荐）**：只补充云端缺失的商品/收藏/分类/图片，不覆盖已有记录；
   - **覆盖同 ID 记录**：用备份覆盖云端同 ID 商品、收藏、图片；适合迁移到新账号或回滚。
4. 二次确认：
   - 第一次确认恢复范围；
   - 第二次输入“恢复”。
5. 等待进度；结束后显示：
   - 商品/收藏/愿望/分类/归属/图片导入数；
   - 跳过已有图片数；
   - 失败数与警告；
   - “下载恢复报告”。

### 避免重复

- 商品按 `(owner_id,id)` 唯一键 upsert；
- 收藏/愿望按 `(owner_id,product_id)`；
- 分类按 `(owner_id,id)`；
- 图片按 `(owner_id,product_id,kind)`；
- 合并模式 `ignoreDuplicates`；覆盖模式只影响同 ID。

### 图片如何对应

- `product_images.product_id` 与商品 ID 一致；
- 恢复时重新上传到当前账号目录，更新 `storage_path`；
- 商品 `image`（合集图红框）与 `product_images`（高清图）互不覆盖；
- 恢复后详情页优先显示高清图；删除高清图回到合集图。

### 原始合集图

- 备份中的 `images/base/` 用于归档校验。
- 恢复时不会把 41MB 原始图重新上传到 Storage：它们是站点静态资源，随项目 `assets/` 部署。
- 如果未来把项目部署到没有 `assets/` 的环境，需要先把 V4 的 `assets/works/gyly/xmx/` 放回项目根目录；用户上传图仍由恢复流程重新上传。

## 5. 恢复结果报告

报告包含：

```text
商品：1538
收藏：2
愿望清单：1
分类：5
分类归属：78
图片：1
跳过已有图片：0
失败：0
警告：...
```

失败不会自动回滚已导入数据；保留原 ZIP，根据报告重试。建议恢复前先导出当前云端完整备份，形成“恢复前快照”。

## 6. 云端数据库备份（平台层）

即使有网站内备份，也建议开启平台层备份：

1. Supabase Dashboard → Database → Backups：
   - 免费计划通常不提供 PITR；Pro 计划可开启 Daily backups / PITR。
2. 可选 GitHub Action：
   - `.github/workflows/supabase-db-backup.yml`
   - 在仓库 Secrets 配置 `SUPABASE_DB_URL`（Postgres 连接串，不是 anon key）；
   - 每天 `pg_dump --format=custom`，保留 30 天 artifact。
3. 可选本机命令：

```bash
pg_dump "$SUPABASE_DB_URL" --format=custom --no-owner --no-privileges \
  --file="xmx-db-$(date +%Y%m%d).dump"
```

数据库 dump 不包含 Storage 文件；图片请用网站完整备份。

---

## 7. 安全

- 备份 ZIP 含个人购买价格、备注，按隐私文件保管。
- 不要把备份 ZIP 上传到公开 GitHub 仓库。
- 不要把 `SUPABASE_DB_URL` / `service_role` 写进前端或提交到仓库。
- 恢复只恢复到当前登录账号，RLS 会阻止跨账号写入。
